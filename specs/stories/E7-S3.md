# E7-S3: Goal progress recompute service triggered on NAV refresh

**Epic:** E7 — Goals & Progress Tracking
**Layer:** Service
**Group:** E
**Depends on:** E7-S1, E6-S2

## Description

Recompute and snapshot each goal's percent_complete whenever the NAV advance-a-day trigger fires, per AC-08.

## Acceptance Criteria

1. After an advance-a-day trigger, exactly one new GoalProgressSnapshot is created per active goal, timestamped to the new snapshot_at.
2. percent_complete is computed using fixed-point arithmetic as current_value divided by target_amount times 100, capped at a documented maximum, never floating-point.
3. A goal whose current_value is 0 produces percent_complete = 0, not a division error.
4. Progress recompute is idempotent for a given price_date; triggering it twice for the same date does not create two snapshots with the same date pairing for the same goal.
5. The recompute service is invoked automatically as part of the advance-a-day flow, verified by a test asserting a new snapshot exists immediately after calling advance-a-day.
