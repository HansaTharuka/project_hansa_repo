# E9-S1: AdvisorOverride repository

**Epic:** E9 — Advisor Workflows
**Layer:** Repository
**Group:** C
**Depends on:** E1-S3

## Description

Persist advisor risk-band overrides as an append-only audit-relevant record, per AC-09 and NFR-02.

## Acceptance Criteria

1. The repository inserts an AdvisorOverride row with customer_id, advisor_id, previous_band, new_band, reason, note, and created_at.
2. No update or delete method exists for AdvisorOverride rows.
3. get_overrides(customer_id) returns the full override history for a customer ordered by created_at descending.
4. Inserting an override with an empty/missing reason is rejected at the repository/service boundary, since reason is mandatory per BRD section 5.1.
5. previous_band in a new override matches the customer's most recent RiskBandAssignment.risk_band at the time of the override.
