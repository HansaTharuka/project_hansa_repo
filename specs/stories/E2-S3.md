# E2-S3: Login UI with role-based redirect

**Epic:** E2 — Authentication
**Layer:** UI
**Group:** E
**Depends on:** E2-S2

## Description

Provide the shared login screen (BRD section 12) that authenticates against the login API and redirects each persona to their respective landing screen based on the JWT role claim.

## Acceptance Criteria

1. Submitting valid credentials navigates the customer role to the customer dashboard, advisor role to the advisor customer list, admin role to the admin console, and compliance role to the audit-log screen.
2. Submitting invalid credentials displays an inline error message without navigating away from the login screen.
3. The email and password inputs are labeled elements associated with their input via for/id, satisfying the BRD's keyboard-navigable, labeled-input accessibility baseline.
4. The JWT is stored client-side and attached as a Bearer token on all subsequent API calls.
5. Refreshing the page while authenticated does not require re-login within the token's validity window.
