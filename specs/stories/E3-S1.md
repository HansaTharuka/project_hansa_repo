# E3-S1: Append-only audit log repository

**Epic:** E3 — Audit Trail
**Layer:** Repository
**Group:** C
**Depends on:** E1-S3

## Description

Create the AuditLogEntry persistence layer as an insert-only table capturing every risk-band assignment, recommendation, rebalancing action, and advisor override, satisfying NFR-02.

## Acceptance Criteria

1. The repository exposes only an insert_audit_entry write function; no update or delete function exists for AuditLogEntry anywhere in the repository module.
2. Each inserted row records entity_type, entity_id, actor_id, actor_role, action, timestamp, and details_json, matching the BRD data-model table.
3. A repository-level test attempts to mutate an existing audit row directly via the repository API and confirms no such method is exposed.
4. Querying by entity_type and a date range returns entries ordered by timestamp ascending.
5. details_json never contains a customer's raw PII or financial-position values beyond entity IDs, per NFR-03.
