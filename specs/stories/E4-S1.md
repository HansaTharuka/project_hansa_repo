# E4-S1: Risk-profile questionnaire and versioned scoring-rule repository

**Epic:** E4 — Risk Profiling
**Layer:** Repository
**Group:** C
**Depends on:** E1-S3

## Description

Persist the >=6-question risk-profile questionnaire and its deterministic scoring rules as immutable, versioned RiskBandRule rows, and store each customer's submitted answers append-only, per AC-01 and NFR-05.

## Acceptance Criteria

1. The repository stores a RiskBandRule row containing version, questionnaire_json (at least 6 questions), scoring_rules_json, published_at, and is_active, and exposes no update method, only insert of new versions.
2. A get_active_rule() repository function returns exactly one RiskBandRule where is_active = true at any point in time.
3. RiskProfileAnswer rows are insert-only per BRD NFR-02; a repository test confirms no update/delete function exists for this table.
4. Seeding the repository with an initial rule version produces version = 1; publishing a second version produces version = 2, and version 1's is_active flips to false while remaining queryable by version number.
5. Each RiskProfileAnswer row records customer_id, question_id, answer_value, and submitted_at.
