# E6-S2: NAV 'advance a day' refresh service

**Epic:** E6 — Asset Price Feed, Holdings & Drift
**Layer:** Service
**Group:** D
**Depends on:** E6-S1

## Description

Implement the manual admin/dev trigger that advances the simulated price feed by one day, generating new NavSnapshot rows and triggering downstream drift/goal recomputation, with no wall-clock scheduler per BRD section 5.1.

## Acceptance Criteria

1. Invoking the advance-a-day service once inserts exactly one new NavSnapshot per AssetClass for the next sequential price_date.
2. Invoking the service a second time on the same simulated day is rejected or is a documented no-op that does not insert duplicate NavSnapshot rows for the same price_date, addressing the BRD double-trigger edge case.
3. After advancing, get_latest_nav for every seeded asset class returns the newly inserted snapshot, not the prior day's.
4. The service is invocable only via an explicit call; no background scheduler, cron, or timer triggers it automatically.
5. A successful advance triggers recomputation of holdings drift for all customers with holdings, without requiring a separate manual step.
