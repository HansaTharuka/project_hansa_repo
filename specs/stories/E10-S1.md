# E10-S1: Versioned rule/template publish repository

**Epic:** E10 — Admin Console
**Layer:** Repository
**Group:** D
**Depends on:** E4-S1, E5-S1

## Description

Extend the risk-profiling and recommendation repositories with admin publish operations enforcing insert-only immutability and a monotonic version constraint to prevent concurrent-publish races, per AC-10 and the BRD's edge-case table.

## Acceptance Criteria

1. Publishing a new RiskBandRule or AllocationTemplate version inserts a row with version = previous_max_version + 1 and sets the prior active version's is_active = false.
2. A DB-level uniqueness/monotonic constraint on (risk_band, version) for templates and version for rules causes a second concurrent publish attempt for the same next version number to fail rather than silently overwrite.
3. No repository method allows mutating allocations_json, questionnaire_json, or scoring_rules_json on an already-published row.
4. Asset-class master CRUD (create/update AssetClass code/name) is supported without affecting historical AllocationTemplate rows that reference the asset class by id.
5. Published rows remain individually queryable by version number after superseding versions are published, supporting in-flight customer pinning.
