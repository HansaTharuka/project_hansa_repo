# E9-S2: Advisor override and manual-recommendation service

**Epic:** E9 — Advisor Workflows
**Layer:** Service
**Group:** F
**Depends on:** E9-S1, E4-S2, E3-S2

## Description

Implement the business logic for an advisor to override a customer's risk band with a reason/note, and to log a manual recommendation, both fully audited per AC-09.

## Acceptance Criteria

1. A valid override request creates an AdvisorOverride row and also creates a new RiskBandAssignment row reflecting new_band, so subsequent recommendation lookups use the overridden band.
2. An override request missing reason is rejected with a validation error and creates no AdvisorOverride or RiskBandAssignment row.
3. A successful override invokes the audit-writer service exactly once with entity_type=AdvisorOverride.
4. Logging a manual recommendation records it against the correct customer_id and advisor_id and invokes the audit-writer.
5. An advisor cannot override a customer who does not exist; the service raises a not-found error.
