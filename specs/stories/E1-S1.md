# E1-S1: Define core domain types and schemas for all entities

**Epic:** E1 — Platform Foundation
**Layer:** Types
**Group:** A
**Depends on:** None (Group A — no dependencies)

## Description

Establish the canonical type definitions (backend Pydantic models and frontend TypeScript interfaces) for every domain entity identified in BRD section 9 (User, Customer, RiskProfileAnswer, RiskBandAssignment, RiskBandRule, AllocationTemplate, Goal, GoalProgressSnapshot, AssetClass, NavSnapshot, Holding, RebalancingRecommendation, AdvisorOverride, AuditLogEntry), so every downstream layer references a single source of truth for shape and constraints.

## Acceptance Criteria

1. A backend types module defines a typed class/schema for each of the 14 entities listed in BRD section 9, with field names and types matching the BRD data-model table exactly.
2. Monetary and percentage fields (target_amount, current_value, nav_value, allocation percentages) are typed as fixed-point/Decimal types, never float, per NFR-01.
3. Enum-constrained fields (role on User, risk_band on RiskBandAssignment/AllocationTemplate, status on RebalancingRecommendation) are defined as closed enums matching the exact literal values from the BRD (role in {customer, advisor, admin, compliance}; status in {pending, accepted, dismissed}).
4. Running mypy against the types module exits with zero errors.
5. A corresponding TypeScript type/interface file exists on the frontend mirroring the same 14 entities' field names and types for shared client-side use.
