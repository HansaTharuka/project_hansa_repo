# E1-S4: Health-check endpoint and structured JSON request logging

**Epic:** E1 — Platform Foundation
**Layer:** API
**Group:** C
**Depends on:** E1-S2, E1-S3

## Description

Expose the app's health endpoint and wire structured JSON logging with request correlation IDs, satisfying NFR-06 (structured logs) and NFR-07 (health endpoint returns 200 within 1 second of successful startup), while ensuring PII/financial data is never logged (NFR-03).

## Acceptance Criteria

1. GET /health returns 200 with a JSON body within 1 second of the application completing startup.
2. Every request/response log line is emitted as structured JSON containing a request correlation ID (e.g., X-Request-ID) that is stable across a single request's log entries.
3. No log line emitted anywhere in the request-logging middleware contains a customer's password, password_hash, or raw financial-position values (NFR-03), verified by a test that asserts these fields are absent or redacted in captured log output.
4. GET /health requires no authentication and returns 200 even when the database has zero rows beyond the seed data.
5. The health endpoint response includes a status field with value ok when the database connection succeeds.
