# E1-S3: Database engine, migrations, and seed-data repository

**Epic:** E1 — Platform Foundation
**Layer:** Repository
**Group:** B
**Depends on:** E1-S1, E1-S2

## Description

Stand up the SQLite database engine, an append-only-friendly migration tool, and repository-layer functions to create and seed Users, Customers, and AssetClass master data so every other domain module can persist through a single, consistent data-access layer.

## Acceptance Criteria

1. Running the migration command against a fresh SQLite file creates tables for all 14 entities defined in E1-S1, with primary keys and foreign keys matching the BRD data model.
2. A seed script inserts 8-10 customers spanning all three risk bands (CONSERVATIVE, MODERATE, AGGRESSIVE), 5-6 asset classes, 2 advisors, 1 admin, and 1 compliance user, matching BRD section 9 seed-data volumes.
3. Every seeded Customer row has kyc_verified = true by default, with at least one seeded customer set to kyc_verified = false to support the AC-06 gating test in E8.
4. Repository functions for User and Customer expose only parameterized queries; a repository unit test asserts a SQL-injection-style input is treated as literal data, not executed.
5. Re-running the migration command on an already-migrated database is idempotent (no duplicate tables, no error).
