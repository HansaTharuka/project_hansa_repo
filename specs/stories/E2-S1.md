# E2-S1: Authentication service (bcrypt verification, JWT issuance)

**Epic:** E2 — Authentication
**Layer:** Service
**Group:** C
**Depends on:** E1-S3

## Description

Implement a service that verifies a user's bcrypt-hashed password and issues a JWT containing the user's id and role claim, enforcing NFR-04's authentication boundary at the controller layer.

## Acceptance Criteria

1. Given a correct email/password pair, the service returns a signed JWT whose decoded payload contains sub (user id) and role matching one of customer|advisor|admin|compliance.
2. Given an incorrect password for an existing email, the service raises a generic invalid-credentials error without revealing whether the email exists.
3. Passwords are verified using bcrypt comparison against the stored password_hash; the service never compares or logs plaintext passwords (NFR-03).
4. The issued JWT expires after the configured jwt_access_token_expiry_minutes from E1-S2; a token decoded after expiry is rejected as invalid.
5. No self-registration path exists in this service; only seeded accounts can authenticate, per BRD section 8.
